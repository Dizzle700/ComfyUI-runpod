# Запуск ComfyUI с шаблонами из SQLite

Для запуска с уже установленными зависимостями используйте
[собственный Docker image](RUNPOD_IMAGE.md). Инструкции ниже относятся к запуску
скриптов поверх обычного RunPod PyTorch template.

Обычный запуск теперь сохраняет текущие версии ComfyUI и Manager. При первом
запуске репозитории клонируются и зависимости устанавливаются. После успешной
установки создаётся `/workspace/ComfyUI/.runpod-setup.json` с версиями Git,
хешами файлов зависимостей и списком установленных пакетов.

На следующих запусках `git pull` не выполняется. `pip install` пропускается,
если отметка соответствует текущим версиям, файлам requirements и Python,
сохранённые пакеты присутствуют с теми же версиями и основные библиотеки
импортируются. Изменение зависимости или отсутствие пакета после пересоздания
контейнера автоматически вызывает установку. Добавление новых пакетов без
изменения старых само по себе не отключает быстрый запуск.

Для обновления ComfyUI и Manager:

```bash
bash runpod_startup.sh --update --templates 89,93,94
```

Для повторного выполнения `pip install` на текущих версиях Git:

```bash
bash runpod_startup.sh --reinstall --templates 89,93,94
```

`--reinstall` повторно проверяет и устанавливает зависимости через pip;
уже удовлетворяющие requirements пакеты pip сохраняет. Удалённый пакет будет
установлен заново. Удаление отметки установки также запускает эту проверку.

В настройках RunPod те же режимы можно включить переменными
`COMFY_UPDATE_ON_START=1` и `COMFY_FORCE_INSTALL=1`. Для обычных запусков
используйте значение `0` или удалите эти переменные. Команды в
`runpod_command.txt` обновляют также `runpod-scripts`, когда
`COMFY_UPDATE_ON_START=1`. Чтобы существующий pod получил эти изменения,
обновите `runpod-scripts` один раз после их публикации в Git.

Отметка ускоряет повторный запуск, но не является lock-файлом для пересоздания
окружения: зависимости с диапазонами версий при новой установке могут получить
другие допустимые версии. Сейчас сохраняются и проверяются фактически
установленные версии.

`templates_models.db` содержит 116 шаблонов, их API JSON и списки моделей. Для
выбора шаблонов используйте их числовые ID:

```bash
python3 comfy_template_startup.py list
```

Пример для **Text to Image (Krea-2 Turbo)**, **Text to Image (Qwen-Image 2512)**
и **Text to Image (Qwen-Image)**:

```bash
bash runpod_startup.sh --templates 89,93,94
```

В RunPod подставьте этот флаг в команду из `runpod_command.txt`. Флаг можно
повторять: `--templates 89 --templates 93,94`. Это пример; можно выбрать любые
ID из списка. `--models Krea` относится к отдельному TXT-файлу `KRea.txt` и
скачивает его раздел **до** старта ComfyUI.

При `--templates` API JSON и обычные workflow JSON экспортируются сразу в
`/workspace/ComfyUI/template_apis/`. ComfyUI и панель запускаются, пока отдельный
процесс скачивает модели. По умолчанию одновременно скачиваются два файла;
`COMFY_TEMPLATE_DOWNLOAD_WORKERS=1..4` меняет это число. Загрузки и ошибки
пишутся в `/workspace/ComfyUI/template-download.log`. Уже имеющиеся непустые
файлы пропускаются. Данные в `/workspace` переживают перезапуск pod.

Проверка состояния и получение API JSON через панель (порт 7860):

```bash
curl -u 'имя_пользователя' 'https://POD_ID-7860.proxy.runpod.net/template-apis'
curl -u 'имя_пользователя' 'https://POD_ID-7860.proxy.runpod.net/template-apis/89/api' > 89.api.json
```

Пароль запрашивается интерактивно; используется тот же `PANEL_USER`/`PANEL_PASS`,
что и у панели. `models_ready` показывает, все ли файлы выбранного шаблона
появились на диске; `missing_models` перечисляет оставшиеся. `missing_nodes`
показывает типы узлов, которых нет в запущенном ComfyUI. `ready` становится
`true`, когда модели есть, сервер API отвечает и узлы доступны. API JSON можно
получить до окончания загрузки, но для выполнения workflow дождитесь `ready`.
Установка моделей не устанавливает отсутствующие custom nodes автоматически.
Если файл уже загружен, но ComfyUI не предлагает его в списке моделей,
обновите интерфейс или перезапустите ComfyUI из панели.

ComfyUI принимает JSON через `POST /prompt`:

```bash
jq -n --slurpfile workflow 89.api.json '{prompt: $workflow[0]}' |
  curl -H 'Content-Type: application/json' \
    --data-binary @- 'https://POD_ID-8188.proxy.runpod.net/prompt'
```

Перед отправкой измените нужные входы API JSON, например текст промпта.
Порт 8188 в текущей конфигурации открыт через RunPod Proxy без авторизации
панели; URL и доступ к нему следует контролировать отдельно.
